## Wire contract at tested source checkpoint
- Native POST /api/mobile/v1/pair, JSON {"code":"<one-time code>"}, no Origin/Cookie/Authorization headers. Success 200 {"deviceId":"...","token":"...","expiresAt":"ISO-8601 UTC"}; code expires after 5 min. Never log code/token.
- Native GET /api/mobile/v1/snapshot, Authorization: Bearer <device token>, no Origin or Cookie. Success 200 direct object (not wrapped in data): version, generatedAt (epoch ms), worker {enabled,online,intervalSeconds}, servers [{id,name,state,observedAt,cpuPercent,memoryPercent,diskPercent,stoppedContainers,failedServices,expiringCertificates,backupStale}]. observedAt epoch ms or null, metrics/counts nullable, backupStale boolean/null. States online/offline/unknown/stale/disabled. No invented totals; unsupported alert metrics remain null.
- Web-only /api/mobile/v1/devices: GET lists own devices and current available servers; POST {label,serverIds} issues {id,code,expiresAt} status 201; DELETE {id} revokes. Existing cookie and same-origin CSRF protections apply. Device bearer cannot access Web API. Current limits: 10 device rows per owner (expired/revoked cleanup on issue), 100 selected servers, bearer TTL 90 days; random code/hash at rest and token/hash at rest. Last access write at most every 15 min. Invalidate on password change/global force logout or current account/permission failure. Manual copy/paste is sufficient; optional QR deferred to keep APK dependency-free.
- Native error responses use {success:false,error} with appropriate status. 401 invalid/revoked/expired -> clear credentials and cached monitoring, require re-pair. 403 reject without bypass; 429 backoff; 503/network errors -> preserve permitted cached observations marked stale, no retry storm. HTTPS only and no redirect/credential forwarding; no trust-all cert handling.
